Report date: 12 October 2026, Malaysia time

All testing on this branch is conducted against an isolated local site with a disposable profile. Existing user data must not be reset or migrated destructively.

### Further hostile scenarios required for P2 signoff

These are pending unless linked to a recorded passing result:

1. Rapid tapping: mode toggles, back, save, cancel, resume, discard and multiple submit events.
2. Active workout interrupted by app switch, low memory termination, restart, offline reload or full PWA reinstall.
3. Storage quota failure, invalid JSON, partially committed registry update, stale migration and concurrent user profile switch.
4. Copied saved routine with deleted exercise ID, duplicate IDs, stale previous session, wrong date and missing measurements.
5. Smart Log with missing reps, missing counts, mixed cardio plus resistance, voice transcription errors, repeated exercise names, contradictory units and long inputs.
6. Resistance variants: timed hold, assisted load, bodyweight, unilateral, dropsets, warmup sets, multiple exercises and edited prior sets.
7. Cardio distance/grade/duration boundaries, multiple activities, treadmill versus road labels, decimal input and duration without distance.
8. Mobility Yoga, Pilates, stretching, recovery and rest day conflicts.
9. iPhone notch and bottom safe area, small viewport, zoomed text, 200% font scaling, keyboard open, sticky save access, system dark/light change and orientation.
10. Security/data: untrusted workout names, HTML injection, overlong notes, per profile isolation and backup restore identity.
11. Live release: tested commit matches production script and assets, service worker cache invalidation, no old P1/P2 duplicate controls and no regression in Calendar/Explore/Progress.

## New execution and failure evidence

* Initial red team run [38169368469](https://github.com/thivaappschat-lab/lastset-training-log/actions/runs/38169368469): **PASS**, all test cases on both mobile Chromium and WebKit, before the second safety hardening patch.
* Production regression run [38168062282](https://github.com/thivaappschat-lab/lastset-training-log/actions/runs/38168062282): **FAIL**, 29 failed and 43 passed. Most failures came from tests requiring intentionally hidden old Today controls to be visible. Do not count these as confirmed application feature failures or discard them: the protected P1 engine is tested through an internal compatibility entry point while new user-facing flows receive direct P2 tests. A corrected source-compatible whole app run is required.
* Original existing whole app suite includes 99 test cases from P0 trust, P1 exhaustive, Smart Log and production browser scripts. Together with 72 P2 cases, the expanded plan is **171 cases per engine, 342 browser executions**, plus JavaScript smoke tests.
* The whole app source-integrity workflow on the red team branch passed its first run. The updated full browser runs are still in progress.
* Following source inspection, P2 v0.20.2 prevents a previously selected profile's unsaved in-memory draft being written under a new profile ID, and allows an intact legacy draft to be recovered even when the new slot contains malformed JSON. Both scenarios are now tested and must pass before merge.
