### Further hostile scenarios required for P2 signoff

These are pending unless linked to a recorded passing result:

1. Rapid tapping: mode toggles, back, save, cancel, resume, discard and multiple submit events.
2. Active workout interrupted by app switch, low memory termination, restart, offline reload or full PWA reinstall.
3. Storage quota failure, invalid JSON, partially committed registry update, stale migration and concurrent user profile switch.
4. Copied saved routine with deleted exercise ID, duplicate IDs, stale previous session, wrong date and missing measurements.
5. Smart Log with missing reps, missing counts, mixed cardio plus resistance, voice transcription errors, repeated exercise names, contradictory units and long inputs.
6. Resistance variants: timed hold, assisted load, bodyweight, unilateral, dropsets, warmup sets, multiple exercises and edited prior sets.
7. Cardio distance/grade/duration boundaries, multiple activities, treadmill versus road labels, decimal input and duration without distance.
8. Mobility Yoga, Pilates, stretching, recovery and rest day conflicts.
9. iPhone notch and bottom safe area, small viewport, zoomed text, 200% font scaling, keyboard open, sticky save access, system dark/light change and orientation.
10. Security/data: untrusted workout names, HTML injection, overlong notes, per profile isolation and backup restore identity.
11. Live release: tested commit matches production script and assets, service worker cache invalidation, no old P1/P2 duplicate controls and no regression in Calendar/Explore/Progress.

### Verified run evidence at the previous revision

* P2 red team run [38169911239](https://github.com/thivaappschat-lab/lastset-training-log/actions/runs/38169911239) on commit `51196970dcf7abdfa3193aed28a2439554e8432f`: **PASS**, 73 of 73 tests on mobile Chromium and 73 of 73 on mobile WebKit, 146 executions total. * Whole App Stress Gate run [38169883813](https://github.com/thivaappschat-lab/lastset-training-log/actions/runs/38169883813) on commit `abfbdaa81d1bd37f5a90ac1a081afddf4dcba665`: **FAIL**, 127 of 128 passed on Chromium and 127 of 128 passed on WebKit. Source integrity passed. The same offline test failed on both engines. Other cancelled runs are not counted as passes.
* Chromium failed job `114560128890` and WebKit failed job `114560128743` both report `tests/e2e/lastset.production.spec.js:583`: `page.evaluate: Test timeout of 40000ms exceeded` while awaiting `navigator.serviceWorker.ready`. Failure traces and screenshots were uploaded as artifacts under run 38169883813.
* Source root cause: `lastset-offline.js` had `location.protocol!=='https:'` as a hard registration gate, so the isolated test server at `http://127.0.0.1:4173/` never registered the service worker even though browsers treat loopback HTTP as a secure context. The wait could therefore never resolve. The patch uses `window.isSecureContext`, permitting loopback development without permitting ordinary insecure HTTP. The test assertion remains unchanged; a successful rerun must prove cache installation and offline behavior.
* The P2 workflow now includes all ten extended tests. Expected P2 coverage is **83 unique cases per browser, 166 executions**, with the existing 73. The Whole App Stress Gate continues to run **128 per browser, 256 executions**, plus source smoke checks. These totals are plans until CI results confirm them.
* All code changes remain on `p2-redteam-20261012`; **production was not deployed**. Existing profiles, history and draft storage are not modified by the offline registration patch.
