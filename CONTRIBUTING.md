# Contributing to LastSet

**LastSet is a proprietary, independently developed product.** Public access
to this repository does not grant a license to republish or commercialize its
source code. See [LICENSE](LICENSE) and [COPYRIGHT.md](COPYRIGHT.md).

## Beta testing and bug reports

Testers may provide reproducible bug reports, observations, and suggestions
through an authorized channel. Use synthetic or disposable workout profiles
and never post passwords, private user data, personal records, unpublished
source code, confidential specifications, or exploitable security details in
public issues or discussions.

If your testing would require nonpublic materials, first sign an appropriate
NDA with the owner. Publicly accessible LastSet materials cannot be made
confidential retroactively merely by an NDA or this document.

## Code and design contributions

This project is **not accepting unsolicited source-code, artwork, or design
contributions for incorporation** unless the owner has approved the scope
and signed a separate written contributor agreement, license, or assignment
that addresses ownership, reuse, attribution, and any third-party rights.

Before a proposed contribution is accepted, contributors must:
1. Confirm that they are entitled to license or assign the material and are
   not using an employer's, client's, or third party's protected work.
2. Identify relevant dependencies and license notices, including AI-assisted
   or generated content and any corresponding platform restrictions.
3. Agree in writing to the applicable contribution/IP terms. A public pull
   request alone does not transfer copyright ownership.
4. Respect repository access restrictions and confidentiality commitments.

For purely textual ideas or bug reports, the owner may ask permission to use
any separately copyright-protected expression if needed. General ideas and
facts are not owned simply because they are mentioned in feedback.

## Access control

Do not share repository tokens, Cloudflare credentials, signing secrets or
private deploy information. External beta testers should receive only the
minimum access necessary to use the public beta, not repository write access.
Security concerns should be reported to the maintainer privately rather
than through a public exploit description.

## Changes to this policy

Any later use of a contributor license agreement should be expressly accepted
by each contributor; publishing a new document here does not create a
retroactive copyright assignment.
